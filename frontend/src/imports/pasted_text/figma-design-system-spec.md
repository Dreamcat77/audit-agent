## 一、角色体系

在设计页面之前，先确定系统中有哪些角色，因为不同角色登录后看到的模块、数据范围、操作权限完全不同。Figma中需要为每个角色设计对应的视图。

| 角色 | 所属部门 | 职责定位 | 系统权限特征 |
|---|---|---|---|
| 需求经办人 | 各业务部门（如刑侦、交警、治安） | 发起采购需求、提交验收申请 | 只看自己发起的项目，操作类权限 |
| 部门负责人 | 各业务部门 | 审核本部门需求合理性 | 看本部门所有项目，审批权限 |
| 采购管理员 | 综合保障部 | 采购全流程管理、文件编制、供应商管理 | 看全部项目，流程推进权限 |
| 财务审核员 | 财务部门 | 预算审核、结算审核、付款审批 | 看全部项目的财务相关环节 |
| 审计员 | 审计部门 | 合同合规审查、结算审计、全程监督 | 看全部项目全流程数据，只读+审核意见权限 |
| 法务审核员 | 法制部门/法律顾问 | 合同法律合规审查 | 看合同环节相关数据 |
| 技术审核员 | 科信办/技术部门 | 技术需求评审、合同技术条款审查 | 看技术相关环节 |
| 分管领导 | 局领导 | 重大事项审批决策 | 看全部项目摘要信息，审批权限 |
| 系统管理员 | 信息技术部门 | 用户管理、权限配置、智能体规则维护 | 全部系统配置权限，不参与业务审批 |

**Figma设计要点**：每个页面设计时，标注清楚"这个区域哪些角色可见/可操作"。建议在Figma中为每个页面做角色权限标注图层。

## 二、模块划分总览

系统共分为8个一级模块，每个模块对应Figma中的一个页面或一组页面：

| 序号 | 模块 | 对应Figma页面 | 核心定位 |
|---|---|---|---|
| 1 | 工作台首页 | Dashboard | 全局入口，待办+数据概览+智能体状态 |
| 2 | 采购需求管理 | 采购需求列表+详情页 | 需求发起→审查→预算编制 |
| 3 | 投标评审管理 | 招标管理+评标工作台 | 文件编制→供应商审查→评标辅助 |
| 4 | 合同内审工作台 | 合同列表+内审详情页 | 合同起草→多维度审查→签署 |
| 5 | 验收结算管理 | 验收页+结算审核页 | 验收组织→结算核对→付款 |
| 6 | 风险预警中心 | 风险看板+预警详情 | 全流程风险监控与分析 |
| 7 | 智能体对话与知识库 | 对话页+知识库检索页 | 自然语言交互+制度检索 |
| 8 | 系统管理 | 用户/角色/规则配置页 | 权限管理+智能体规则维护 |

## 三、各模块详细设计

### 模块1：工作台首页

**页面定位**：用户登录后的第一屏，根据角色展示不同的概览信息和待办。

**页面区域划分**：

| 区域 | 位置 | 内容 | 数据来源 |
|---|---|---|---|
| 顶部导航栏 | 页面顶部 | 系统Logo + 一级模块导航 + 全局搜索 + 用户头像/消息通知 | 固定结构 |
| 欢迎横幅 | 导航下方 | 问候语 + 今日待办数量 + 智能体处理摘要 + 日期 | 根据当前用户角色动态生成 |
| KPI数据卡片 | 横幅下方 | 在审项目数、风险预警数、智能体审核次数、平均审核耗时 | 全局统计数据 |
| 待办事项列表 | 左侧主区域（占2/3） | 按紧急程度排序的待办项，每项含项目名称、类型图标、金额、智能体预审结果标签 | 当前用户的待办任务队列 |
| 智能体状态面板 | 右侧或左下 | 6大引擎运行状态、今日处理量、准确率、各引擎工作量分布 | 智能体监控数据 |
| 风险预警摘要 | 右侧栏 | 最近风险预警列表（红/黄/蓝三级），每项含风险标题、关联项目、时间 | 风险预警引擎 |
| 审计动态时间线 | 右侧栏底部 | 智能体操作日志、流程节点变更、制度更新等动态 | 系统操作日志 |

**不同角色的首页差异**：

| 角色 | 首页重点展示 |
|---|---|
| 需求经办人 | 自己发起的项目进度 + 待提交的验收申请 |
| 部门负责人 | 本部门待审批需求 + 本部门项目统计 |
| 采购管理员 | 全部待推进项目 + 待编制文件 + 供应商动态 |
| 财务审核员 | 待审核预算 + 待审核结算 |
| 审计员 | 全程风险预警 + 待审查合同 + 智能体审核意见 |
| 分管领导 | 全局KPI + 重大项目摘要 + 待审批事项 |

**场景示例**：
- 审计员登录后，首页优先展示智能体昨夜自动审查的结果——"移动采集终端采购合同发现3处条款偏离，红色拦截"，点击直接跳转到合同内审详情页
- 分管领导登录后，看到的是"本月采购总额、节约资金率、风险项目数"等宏观指标

### 模块2：采购需求管理

**页面定位**：管理采购需求的发起、初审、市场调研、预算编制、需求审查全过程。

**页面结构**：列表页 + 详情页（点击列表项进入）

#### 2.1 采购需求列表页

| 区域 | 内容 |
|---|---|
| 筛选区 | 按状态（草稿/初审中/审查中/已通过/已退回）、部门、采购类型、金额范围、时间筛选 |
| 操作按钮 | "新建采购需求"按钮（需求经办人可见） |
| 列表表格 | 列：需求编号、项目名称、申请部门、采购类型、预算金额、当前状态、智能体预审标签、创建时间、操作 |
| 智能体标签列 | 每行显示智能体预审结果：绿色"通过"/黄色"提示"/红色"预警"/灰色"未审核" |

#### 2.2 采购需求详情页

详情页采用**左右分栏**布局，左侧为业务表单区，右侧为智能体辅助面板。

**左侧 - 业务表单区**（按流程节点分Tab或分区块展示）：

| 区块 | 内容 | 操作角色 |
|---|---|---|
| 需求基本信息 | 项目名称、采购品目、物资名称、规格型号、数量、技术要求描述、使用场景说明、期望交付时间 | 需求经办人填写 |
| 需求附件 | 需求说明书、技术参数文件、参考方案等上传 | 需求经办人上传 |
| 市场调研记录 | 调研供应商列表、报价记录、历史成交价格参考 | 采购管理员填写（或智能体自动填充） |
| 预算信息 | 预算总额、资金来源（财政拨款/专项经费/其他）、预算明细表（品名×单价×数量）、测算依据 | 需求经办人/采购管理员填写 |
| 审批流程区 | 当前审批节点、审批人、审批意见、审批历史记录 | 各级审批人操作 |
| 关联信息 | 关联的年度采购计划、关联的项目编号 | 系统自动关联 |

**右侧 - 智能体辅助面板**（实时联动左侧内容）：

| 智能体卡片 | 触发时机 | 展示内容 |
|---|---|---|
| 需求合理性校验 | 需求经办人保存需求时 | 与历史同类采购比对：数量是否异常偏高、规格是否超出常规配置、是否在年度计划范围内 |
| 市场价格参考 | 需求保存后自动触发 | 自动检索政府采购平台历史成交价，生成价格区间建议："同类物资历史成交价区间 ¥3,200-3,800/台，本次填报 ¥4,500/台，偏高14%" |
| 预算合规预检 | 预算金额填写后触发 | 校验是否超出资产配置标准、是否超出经费支出标准，超限项标红列出 |
| 需求审查意见 | 进入需求审查节点时触发 | 对照《政府采购需求管理办法》逐条检查：非歧视性（是否指向特定品牌）、竞争性（资格条件是否过严）、政策合规性，生成结构化审查意见 |
| 法规依据推荐 | 任何节点用户提问时 | 自然语言检索制度库，返回相关法规条款 |

**流程走向**（详情页内体现为审批流程图/进度条）：

```
需求提出(经办人) → 需求初审(采购管理员) → 需求论证(评审会议) 
→ 市场调查(采购管理员) → 预算编制(经办人) → 预算审核(财务) 
→ 预算审批(分管领导) → 需求审查(审查小组)
```

**审核机制**：

| 节点 | 审核人 | 智能体参与 | 审核标准 | 通过/退回规则 |
|---|---|---|---|---|
| 需求初审 | 采购管理员 | 自动校验需求合理性和计划匹配 | 需求明确、在计划内、数量合理 | 智能体红色拦截时必须填写处理意见才能通过 |
| 需求论证 | 评审会议 | 会前生成参考材料包 | 专家论证通过 | 会议记录上传后自动流转 |
| 预算审核 | 财务审核员 | 自动校验标准合规 | 不超资产配置标准、不超经费标准 | 超标项必须调整或提供专项说明 |
| 预算审批 | 分管领导 | 生成审批摘要卡片 | 金额在权限范围内 | 一键审批或退回 |
| 需求审查 | 审查小组 | 自动生成审查意见 | 非歧视性、竞争性、合规性 | 智能体标记的红色项必须逐条确认 |

### 模块3：投标评审管理

**页面定位**：管理采购文件编制、供应商报名审查、开标评标全过程。

**页面结构**：招标管理列表页 + 招标详情页 + 评标工作台

#### 3.1 招标管理列表页

| 区域 | 内容 |
|---|---|
| 筛选区 | 按状态（编制中/审核中/已发布/开标中/评标中/已定标）、采购方式、时间筛选 |
| 列表表格 | 列：项目编号、项目名称、采购方式、控制价、报名供应商数、当前状态、智能体标签、操作 |
| 操作 | 查看详情、编制文件、发布、开标、评标（按状态和角色显示不同按钮） |

#### 3.2 招标详情页

| 区块 | 内容 | 操作角色 |
|---|---|---|
| 采购方式选择 | 显示已选方式（公开招标/竞争性磋商/询价等）+ 智能体推荐理由 | 采购管理员选择 |
| 采购文件区 | 技术要求、商务要求、评标办法、合同条款草案——分Tab展示，可在线编辑 | 采购管理员编制 |
| 控制价信息 | 控制价金额、编制依据、审核状态 | 审计员审核 |
| 文件审核流 | 需求部门确认→业务部门审定→招标办确认→法律顾问审查，逐级流转记录 | 各级审核人 |
| 发布管理 | 公告内容、发布渠道、公告期倒计时 | 采购管理员操作 |
| 供应商报名区 | 报名供应商列表、资质材料、资格审查结果 | 采购管理员/资审人员 |

**智能体辅助面板**：

| 智能体卡片 | 触发时机 | 展示内容 |
|---|---|---|
| 采购方式推荐 | 进入方式选择时 | 根据金额和品类自动推荐方式+"根据《政府采购法》第XX条，金额超过XX万应采用公开招标…" |
| 招标文件辅助编制 | 进入文件编制时 | 自动匹配模板生成初稿，高亮需要填写的变量字段 |
| 控制价合理性审核 | 控制价填写后 | 比对历史成交价："同类项目历史成交均价¥78万，本次控制价¥95万，偏高22%" |
| 供应商关联分析 | 报名截止后 | 自动查询所有报名供应商的股权结构、法人代表、历史合作关系，绘制关联关系图，标出疑似关联企业 |
| 资格自动审查 | 供应商提交资质后 | OCR识别营业执照等信息，交叉核验工商数据，自动标记不符条件者 |

#### 3.3 评标工作台

这是投标评审的核心页面，评标专家使用。

**页面区域**：

| 区域 | 位置 | 内容 |
|---|---|---|
| 项目摘要栏 | 顶部 | 项目名称、采购方式、控制价、投标供应商数、评标办法说明 |
| 供应商Tab切换 | 左侧 | 列出所有投标供应商，点击切换查看不同供应商的投标文件 |
| 投标文件展示区 | 中间主区域 | 分Tab展示：商务标（报价表）、技术标（技术方案）、资质文件——在线查看 |
| 评分区 | 右侧 | 按评标办法设定的评分项逐项打分，每项含分值范围、评分说明 |
| 智能体辅助栏 | 右侧底部/侧边栏 | 实时分析结果 |

**智能体在评标中的具体功能**：

| 功能 | 说明 |
|---|---|
| 技术标智能解析 | NLP解析投标文件技术标，提取关键应答点，对照招标文件技术要求，逐条标注"已应答/部分应答/未应答" |
| 投标文件查重 | 多维度比对所有投标文件（企业资质、人员信息、技术方案文本、附图表格），计算两两之间的雷同率，超过阈值的组合标红 |
| 报价异常分析 | 分析所有投标报价的分布，标记异常低价（低于均值30%以上）和异常高价 |
| 打分偏差预警 | 实时监控各位专家的打分，当某专家打分与均值偏差超过设定范围时，提示"专家A在技术方案项打分显著偏低，偏差-25%" |

**审核机制**：

| 节点 | 审核人 | 智能体参与 | 审核标准 |
|---|---|---|---|
| 采购文件审定 | 需求部门→业务部门→招标办→法律顾问 | 逐级自动合规校验 | 技术要求无歧视、评标办法合规、合同条款合法 |
| 控制价审核 | 审计员 | 自动比价 | 不高于市场价、不高于历史成交价 |
| 供应商资格审查 | 资审人员 | 自动OCR+工商核验 | 营业执照有效、资质符合要求、无不良记录 |
| 评标结果审核 | 采购管理员→决策层 | 评标过程合规校验 | 程序完整、打分无异常、查重无重大风险 |

### 模块4：合同内审工作台

**页面定位**：这是智能体价值最集中的模块，实现合同与招标文件、投标文件的三方比对审查。

**页面结构**：合同列表页 + 合同内审详情页

#### 4.1 合同列表页

| 区域 | 内容 |
|---|---|
| 筛选区 | 按状态（起草中/技术审查/商务审查/法律审查/审计审查/审批中/已签署）、金额范围、时间 |
| 列表表格 | 合同编号、项目名称、供应商、合同金额、当前审查环节、智能体审查标签（绿色/黄色/红色）、操作 |
| 快捷操作 | "新建合同"（从已定标项目生成）、"批量审查"（审计员可批量查看智能体已审核通过的合同） |

#### 4.2 合同内审详情页

这是最复杂的页面，采用**三栏布局**：

**左栏 - 合同文件区**：

| Tab | 内容 |
|---|---|
| 合同正文 | 合同全文，可在线查看/编辑，关键条款高亮标注 |
| 招标文件 | 关联的招标文件原文（只读参考） |
| 投标文件 | 中标供应商的投标文件原文（只读参考） |
| 附件 | 合同附件、补充协议等 |

**中栏 - 智能体审查结果区**（核心区域）：

| 审查维度 | 展示内容 | 预警级别 |
|---|---|---|
| 三方一致性审查 | 逐条比对合同 vs 招标文件 vs 投标文件，列出：价款金额是否一致、工期是否一致、质量标准是否一致、项目经理是否一致、技术规格是否一致——每条标注"一致/偏离/缺失" | 偏离项标红 |
| 商务条款审查 | 付款比例是否合规（如预付款不超30%）、付款节点是否合理、质保金比例是否符合规定、发票要求是否明确 | 不合规项标红 |
| 法律风险识别 | 模糊表述（如" approximately"、"左右"）、权责不对等条款、违约责任缺失或过轻、知识产权约定不明、争议解决条款缺失 | 按风险等级标黄/标红 |
| 保密条款审查 | 涉密项目是否包含保密条款、保密等级是否匹配、保密期限是否合理 | 缺失标红 |
| 修改建议 | 针对每个风险条款，智能体生成修改建议文本，关联对应法规条款 | 建议文本可直接采纳 |

**右栏 - 审批流程区**：

| 内容 | 说明 |
|---|---|
| 审批流程图 | 可视化展示当前审批进度：技术审查→商务审查→法律审查→审计审查→签署 |
| 各环节审查意见 | 每个审查环节的审查人、审查意见、通过/退回记录 |
| 合同摘要卡片 | 供审批人快速了解：合同金额、供应商、关键条款摘要、智能体风险提示汇总 |
| 操作按钮 | 通过/退回/添加意见（按当前角色和环节显示） |

**审核机制（多维度并行审查）**：

| 审查环节 | 审查人 | 审查重点 | 智能体辅助 | 通过规则 |
|---|---|---|---|---|
| 技术条款审查 | 技术审核员/需求部门 | 技术规格、质量标准、交付要求与招标文件一致 | 自动比对一致性，偏离项标红 | 红色项必须处理 |
| 商务条款审查 | 财务审核员 | 付款条件、金额、进度、发票 | 自动校验合规性 | 不合规项必须修改 |
| 法律合规审查 | 法务审核员 | 合法性、违约责任、知识产权、保密 | 自动风险识别+修改建议 | 高风险项必须修改 |
| 审计合规审查 | 审计员 | 合同与招标/投标文件一致性、实质性偏离 | 三方自动比对 | 偏离项必须确认 |
| 审批签署 | 分管领导 | 综合决策 | 生成摘要卡片 | 在权限内一键审批 |

**场景示例**：
- 审计员打开合同详情页，智能体已在三栏中间区域标出5处红色偏离项——"合同价款¥87.6万，中标价为¥84.9万，偏离+3.2%"，审计员点击该条，自动定位到左栏合同正文对应条款，可直接添加审查意见"要求修改为中标价金额"

### 模块5：验收结算管理

**页面定位**：管理到货验收、结算审核、付款审批全流程。

**页面结构**：验收管理页 + 结算审核页

#### 5.1 验收管理页

| 区域 | 内容 |
|---|---|
| 筛选区 | 按状态（待验收/验收中/已验收/验收不通过）、项目、时间 |
| 列表表格 | 项目名称、合同编号、供应商、验收状态、验收日期、智能体标签 |
| 验收详情区（点击进入） | 见下方 |

**验收详情页**：

| 区块 | 内容 | 操作角色 |
|---|---|---|
| 合同信息摘要 | 合同编号、金额、供应商、技术要求摘要（从合同自动提取） | 只读 |
| 验收清单 | 智能体根据合同技术要求自动生成的逐项验收清单——每项含检查项名称、标准要求、实际结果、是否合格 | 验收人员逐项填写 |
| 验收附件 | 验收照片、检测报告等上传 | 验收人员上传 |
| 验收结论 | 合格/部分合格/不合格 + 验收意见 | 验收小组组长填写 |
| 验收审核 | 审核验收程序完整性、人员合规性 | 采购管理员/审计员 |

**智能体功能**：

| 功能 | 说明 |
|---|---|
| 验收清单自动生成 | 从合同技术条款中提取所有可验收项，生成结构化清单，免去人工逐条录入 |
| 验收合规校验 | 校验验收人员是否符合岗位分离要求（验收人与采购经办人不能是同一人）、验收程序是否完整 |
| 异常项标红 | 验收结果中不合格项自动标红，不合格率超过阈值时整体验收标黄 |

#### 5.2 结算审核页

| 区块 | 内容 | 操作角色 |
|---|---|---|
| 结算申请信息 | 申请金额、申请说明、结算附件（发票、验收报告等） | 需求经办人/供应商提交 |
| 四要素核对区 | 智能体自动提取并交叉核对：合同金额、已付金额、本次申请金额、发票金额——四项数据并列展示，不一致项标红 | 智能体自动执行 |
| 合同匹配核验 | 结算金额与合同约定比对，如有变更自动追溯变更审批记录 | 智能体自动执行 |
| 金额复核 | 自动复核计算准确性，检查是否超预算/超合同 | 智能体自动执行 |
| 审核意见 | 审核人填写意见，通过/退回 | 财务审核员/审计员 |
| 付款审批 | 审批摘要卡片（金额、核对结果、风险提示），一键审批 | 财务负责人/分管领导 |

**审核机制**：

| 节点 | 审核人 | 智能体参与 | 审核标准 | 通过规则 |
|---|---|---|---|---|
| 结算要素核对 | 财务审核员 | 自动四要素交叉核对 | 合同金额≥已付+本次申请、发票金额=申请金额 | 不一致项必须说明原因 |
| 合同匹配核验 | 审计员 | 自动比对合同+追溯变更 | 结算金额不超合同金额（变更后不超变更后金额） | 超合同必须先走变更审批 |
| 金额复核 | 财务审核员 | 自动计算复核 | 计算准确、不超预算 | 超预算拦截 |
| 付款审批 | 财务负责人/分管领导 | 生成摘要卡片 | 在审批权限范围内 | 一键审批或退回 |

**场景示例**：
- 财务审核员打开结算页，智能体已自动完成核对——绿色标签"四要素一致"，但标出一个黄色提示"本次结算后累计付款达合同金额95%，剩余5%为质保金，请确认质保期未满"，审核员确认后一键通过

## 四、全局交互机制

以下是跨模块的通用交互设计，Figma中每个页面都应遵循：

### 4.1 智能体意见卡片规范

每个智能体审核结果统一以卡片形式展示在对应流程节点旁：

| 卡片元素 | 说明 |
|---|---|
| 卡片标题 | 审核维度名称（如"三方一致性审查"） |
| 预警级别标签 | 绿色"通过" / 黄色"提示" / 红色"拦截" |
| 审核结果摘要 | 一句话结论（如"发现3处条款偏离"） |
| 详情展开 | 点击展开查看逐条明细 |
| 操作按钮 | "查看详情"（跳转到对应文件位置）/"采纳建议"/"忽略并说明" |
| 法规依据 | 关联的法规条款链接 |

### 4.2 三级预警与流程联动

| 预警级别 | 页面表现 | 流程影响 |
|---|---|---|
| 绿色（通过） | 绿色标签，卡片可折叠 | 不阻塞流程，人工可快速确认通过 |
| 黄色（提示） | 黄色标签，卡片默认展开 | 不阻塞流程，但需人工阅读后选择"知悉继续"或"暂停处理" |
| 红色（拦截） | 红色标签+页面顶部横幅提醒 | 阻塞流程，必须人工处理并填写处理意见后才能继续流转 |

### 4.3 全流程进度可视化

每个项目详情页顶部都有一个**横向流程进度条**，展示39个节点的完成状态：

| 状态 | 表现 |
|---|---|
| 已完成 | 实心圆+绿色 |
| 当前节点 | 实心圆+蓝色脉冲动画 |
| 智能体待处理 | 空心圆+紫色边框 |
| 未到达 | 空心圆+灰色 |
| 有风险预警 | 实心圆+红色边框 |

点击任意节点可跳转到对应环节的详情。
