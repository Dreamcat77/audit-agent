ScanDiag_v2：预算扫描PDF脱敏诊断（不是更新包）

把压缩包传到甲方服务器，在包所在目录执行一条命令：
  tar -xzf ScanDiag_v2.tar.gz && sudo bash ScanDiag_v2/run.sh --ocr-probe --model-probe

不用重新上传业务材料，不重启、不升级、不改数据库或原分析结果。
默认按服务器当天及前后各一天，读取最近100份预算材料；附带最近20批采购/合同的技术状态。
不是只查17点。若运行日期不是上传当天，可加 --day 2026-10-30。
查询到上限时会记录limitReached；需要更大范围可用 --limit 300。

取证内容：
- 上传任务状态、提取和结果快照是否存在、已保存金额信息数量与被拒原因。
- 实际运行版本、OCR/模型时间配置、逐页读取及模型分段技术日志。
- 最多检查40个来源，PDF逐页原生文字最多采样8页，四页PDF会全部检查。
- --ocr-probe：对范围内最近3份可读的四页预算PDF，逐页渲染并调用正在运行的OCR。
  共最多12页，串行调用，单页读取最多600秒、探测总等待最多2400秒。
  仅导出逐页字数、预算/申报/批复等固定线索数量、大写数字数量和置信度等统计。
  使用现有OCR并发管理，不另起Paddle实例。可能需要几分钟；慢时请等脚本结束。
- --model-probe：使用当前甲方模型配置，最多2次串行调用，每次180秒。
  优先取上述复读得到的预算附近小段，用BUDGET业务提示做对照。
  只导出提取类型数量、引用支持数量、失败代码，不导出原始模型回答。
  它是局部诊断，不代表重新执行了整份材料的正式分析。

数据库预算快照保存的是已提取信息及引用片段，不是完整OCR正文。
因此脚本不会把“引用片段字数为0”直接说成“OCR没读到”。
复读成功也不等于证明当时那次上传读成功，需与原任务日志、信息核验原因一起判断。
OCR或模型探测失败仍会导出已有诊断信息，不会把失败解释成材料本身没有金额。

隐私：正文、图片、PDF、文件名、单位/人员名称、实际金额、访问地址、账号、密钥、
原始日志和模型原始回答均不进导出包。脚本在本机临时读取正文用于统计，临时片段
不会混入导出目录，结束时清除。使用既有模型/OCR地址，不接入其他模型服务。

结束显示DIAG=COLLECTED及OUTPUT=.../ScanDiag-日期-时间-进程号.tar.gz。
只回传OUTPUT对应的压缩包；COLLECTED表示已收集，不表示所有阶段都通过。
文件包括database.json、pdf.json、ocr.json、model.json、events.jsonl、runtime.json、
findings.json、summary.json。未拿到现场结果前，不能把本地或26验证当成现场故障已解决。
