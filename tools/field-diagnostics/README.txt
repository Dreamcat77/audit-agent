FieldDiag_v1：采购、PDF/OCR、合同八大项现场诊断

在甲方服务器解压后，进入上一级目录执行：

  sudo bash FieldDiag_v1/run.sh --model-probe

不需要重新上传文件；不更新应用、不重启服务、不改数据库。
使用已运行服务的配置和现有 JDK17/Python3.11，不安装软件。
自动检查服务器当天及前后一天的记录；数据库操作仅SELECT，不写入业务数据。
默认每个模块最近20批；需要指定某天可加 --day 2026-10-29。

--model-probe 的含义：
在服务器本地，从已保存的采购文本中优先选择预算附近内容，用当前应用配置
的模型做最多2次串行字段提取。每次最多180秒，不重试，不重新审核整份文件。
这些小段正文会发送给当前配置的模型服务；不得把模型地址改为未经授权的服务。
探测不会补写业务结果。省略 --model-probe 就不再调用模型。
通常几分钟；若模型慢，整段探测最多390秒后明确记录超时。

诊断内容：
1. 采购：保存文字数量、固定预算/采购人/金额线索、已有字段类型、原文核验数量、
   审查输入覆盖字数、模型拒绝/超时记录；帮助区分没读到、没提取到、被校验舍弃。
2. PDF：最多4份、每份最多256页的原生文字及页面旋转信息，单份最多35秒。
   不重新执行耗时OCR；扫描图片的真实朝向不能仅由PDF旋转标签断言，需结合
   现有OCR旋转、置信度、耗时及错误记录判断。超过抽查范围会明确标记。
3. 合同：文件名的固定类别线索、已保存正文线索、分段结果、材料类别决定、
   建档所需字段是否存在、正式合同/五步审核/报告状态。
4. 版本：运行中JAR、前端入口、指定AI源码的哈希；不要求现场必须是v14。

保密边界：
数据库正文、原文件内容及模型结果仅在服务器本地读取；不进入导出包。
不导出原文件名、项目/单位/人员名称、实际金额、模型原始回答、提示词、
数据库连接串、模型地址或密钥。仅固定公开关键词、技术枚举、数量、页码、
时间及关联UUID；不接受模型自由生成的新字眼作为导出内容。
必要的临时片段放在私有临时目录，正常结束/普通异常会清理；不重打包原始日志。

运行后会显示：
  DIAG=COLLECTED
  OUTPUT=.../FieldDiag-日期-时间.tar.gz

只把 OUTPUT 对应压缩包发回即可。COLLECTED表示收集结束，不表示所有检查成功；
各阶段失败/不可见/未配置会在对应JSON中单独记录，不会冒充“源文件没有信息”。
测试环境验证不代表甲方原始文件已经验证；拿到现场包后再按证据定修复范围。
