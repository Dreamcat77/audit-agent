ScanDiag_v1：采购扫描PDF现场诊断（仅取证，不是更新包）

解压到新目录，进入有ScanDiag_v1文件夹的目录，一次执行：
  sudo bash ScanDiag_v1/run.sh

不需要重新上传，不重启、不更新、不写数据库、不重跑整份OCR或模型。
自动从当前服务取配置，查询服务器当天及前后一天的最近20个采购批次。
需要特定日期可加 --day 2026-10-30；需要扩大范围可加 --limit 50。
通常几十秒至几分钟；最多8份PDF逐页检查（单份最多512页/60秒），不做渲染。

检查：
1. 每批及文件的读取/提取状态、实际保存文字量、预算/限价等固定线索数量。
2. 原PDF页数、逐页原生文字数量、旋转标签；对照数据库保存文字的页码覆盖。
3. OCR空页、旋转选择、初始化/识别耗时、容量等待、页数/文字/时间上限等日志。
4. 模型分段总数/已完成段数、累计调用/耗时、终态原因、已核验事实数量。
5. 运行JAR中的页数默认值、可观测配置覆盖、AI实际生效的非敏感数值配置。
6. findings.json按文件关联已有证据；没有证据时只标待查，不认定材料没有信息。

默认不额外调用模型；确需小范围模型对照时可另加 --model-probe。
该选项最多2次串行调用，每次180秒，使用当前现场配置的模型；不改已有结果。
探测只针对已经保存的文字，不能替代扫描件OCR或证明整份文件提取完整。

导出不含正文、PDF、图片、截图、原始日志、文件名、单位名、实际金额、
模型原始回答、数据库连接串、地址、账号或密码；仅技术状态、计数、页码、
时间及关联UUID。服务器本地读取正文用于统计，私有临时输入不进入导出包。

结束显示DIAG=COLLECTED及OUTPUT=.../ScanDiag-时间.tar.gz。
只把OUTPUT对应压缩包发回。COLLECTED表示已收集，不表示各阶段检查通过。
本工具本地测试通过不等于现场问题已定位；收到现场结果后再确定修复。
