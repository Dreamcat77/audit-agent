AuditAgent 架构绑定离线更新包

适用：包内 VERSION.txt 指定的麒麟 V10 SP3 2403 aarch64 既有安装。包内不含数据库密码、AI 密钥、Nginx 配置、业务数据或 RPM，不重装运行时。架构不匹配时正式更新会停止。

更新包已解压到新目录并完成SHA256核对后，现场只需运行一次：
  sudo bash update.sh

也可单独运行只读预检：
  sudo bash update.sh --check

正式命令自动检查当前Nginx返回的前端资源、DM8结构、服务用户Python依赖和活动任务。不要求另跑`--check`或提供恢复确认文件。正式更新先停Java/AI服务，再做增量DDL并切换新release；真实结构漂移、其他模块活动任务或健康检查失败会停止并输出stage/reasonCode，不会自动修表或重放DDL。

若预检明确被采购AUDIT_CASE中的UNKNOWN记录阻断，update.sh会使用包内工具复核任务数量及租约。只有恰好一条且租约已过期时，才停止Java/AI服务，事务收口并保留文件、事实、报价和报告，再自动重试更新。租约仍有效、多条记录、状态冲突或其他模块任务会停止且不修改任务。此处理不需要另传工具包。

本包还会在同一 DM8 事务中幂等补齐采购、预算、合同三个个人角色账号。若账号不存在，更新时会交互提示输入一次三个新账号共用的初始密码（至少8位，输入不回显）；若账号已存在，仅补缺少的角色关系，不改密码、状态、历史数据。账号数据提交后不会因应用代码回退而撤销。

管理员可在“人员管理”中添加普通人员。普通账号均可使用三大业务模块和共享黑名单，上传及结果按账号隔离，管理员可查看所有账号数据。

更新会自动补齐服务对象身份表，保留已有配置。只有首次没有配置时，命令内会提示输入正式单位名称一次；已有配置不会再询问。名称仅保存本机数据库，用于审查立场和模型调用时的名称保护。自动化部署也可设置 AUDIT_CLIENT_FORMAL_NAME 及用分号分隔的 AUDIT_CLIENT_ALIASES。此配置提交后不会随应用回退撤销。

如包内 client-identity-aliases.txt 包含本次批准增加的名称，更新时自动幂等追加到已有身份配置，不要求重新填写、不覆盖原正式名称；日志只记录数量。长名称允许同辖区内单字OCR偏差，短简称仍依配置或原文定义识别，不把异地单位、分局或相似公司当成我方。模型调用中的原始OCR写法同步脱敏。

PDF OCR 请求上限设为每份文档最多四页并行、Python最多四个独立单线程进程；启动时仍按 CPU affinity、cgroup v2 配额和可用内存准入，资源信息不可确认时保持单路，资源不足时自动降到可用路数。CPU_THREADS仍为1，MKLDNN关闭。是否实际达到四路需检查启动事件OCR_POOL_CONFIGURED的worker_count及处理期间的子进程，不以静态配置或空闲时top截图代替。

本包按用户要求不自动备份数据库或业务文件，也不检查备份恢复记录。更新器会在`/opt/audit-agent/update-backups`保留旧应用文件用于应用级回滚；DDL成功后回滚应用不会撤销DDL。此次属于明确选择的无备份更新方式，请勿将应用文件副本当作数据库备份。真实Schema漂移、部分迁移状态和其他活动任务仍会停止更新，不会自动修表或重放DDL。

Nginx root 必须是 /opt/audit-agent/current/frontend/dist。现有 AI 网关地址、密钥、模型名继续从现场配置读取。失败时保留脚本输出的更新日志及恢复目录；人工应用回滚时，将更新日志中的恢复目录作为参数：sudo bash rollback.sh "恢复目录绝对路径"。支持当前版本生成的版本目录。

完成后 Ctrl+F5，并分别用预算、采购、合同材料现场验证。模型网关白名单、协议兼容、客户 ARM OCR 和合同正式五步审查仍需现场验收。

自动案件：预算按上传批次输出并逐步显示已保存的结果；采购整批上传完成金额核对、黑名单、预审和F10；合同生成有依据的完整或部分报告并保留八项位置。围串标和拆分采购没有执行的检查不表示已合规。现有业务表及历史数据保留。

本次优化按一批一个项目整理重复信息，依原文标签区分项目编号、合同统一编号、采购编号与主体角色；重复展示合并全部证据，不随意抹去真实不同供应商、分包、年度、金额或意见。预算新分析加强资金用途、审批条件和材料矛盾审查；仅识别不清、没上传某文件或编号类型不同不当成材料缺陷。新提示词用于更新后的新分析；不会批量重跑历史任务。

三模块处理页可取消任务。取消后阻止迟到结果重新发布，后台等待实际工作线程退出后清理临时文件。最小取消记录和操作审计保留；合同已提交的解析事实、正式合同及引用证据保留，避免破坏已有记录。

如部署制度不允许无备份更新，请勿运行本包。应用回退不会撤销已成功执行的增量DDL。

内部99-audit-v10.conf及deploy/update-v10为兼容以前安装而保留的稳定管理标识，不代表本包仍是旧代码。应用提交和版本以VERSION.txt及manifest为准。
