## 实测发现与修复

1. 招标部分分段模型返回 `{}`，原来整次分析失败。提示明确要求 `findings`；结构不合规时仅允许一次带原文、受总预算约束的结构修复。持续无效或证据不匹配仍失败，绝不当作无风险。
2. 不同风险类别共用同一段原文时被过度合并。合并要求同类别，保留“品牌/排他/地域/资质/条款一致性”等不同问题；同类别重复提示仍去重。
3. 合法数字科目码 `31002` 和两字名称“设备”被误报。允许这些实际输入，纯标点编码和纯数字名称等负例仍拒绝。
4. 报告总评原先笼统套用黑名单和预算异常。现在按实际已观察到的模块/类别提示，不编造黑名单命中，不强加审批流程。
5. 大写金额 `壹拾万元整。` 的末尾中文句号导致格式错误。仅允许完整金额末尾一个中文句号/分号，双句号、待定后缀、多金额歧义等仍拒绝。金额计算仍使用 BigDecimal。
6. 混合格式实测中 CSV/PPT/XLS 各出现一次 Java→AI SocketException，AI 服务没有重启。新增同一不可变来源最多一次连接恢复并关闭跨请求连接复用；HTTP 错误、无效业务/JSON 响应不重试。实际网络根因没有凭异常类型武断认定。
7. 采购统计原先是演示固定数字，改为查询项目数、本页项目、本页预算合计，统计范围明确，布局不变。
8. 模型意见中的 `docx/body/paragraph:...` 在展示层替换为“原文条款”；保存的证据定位和原文不改。浏览器复核发现报告只显示90天原文、丢失与30天冲突的理由，已补报告 API 的 riskReason，并在原有条目下显示核对意见和建议。
9. 预算完成后统计卡仍称“待校验材料”，改为“本批材料”及实际已上传数量，不改变页面样式。
