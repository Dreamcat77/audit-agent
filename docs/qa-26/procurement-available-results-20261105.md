# 采购按现有材料出结果

目标：工作人员上传现有材料即可得到有依据的内容。单份投标文件可以提供项目、供应商、报价和履约安排；未上传其他阶段的材料本身不作为风险，未完成的核对也不冒充通过。

## 实现边界

- `DurableMaterialExtractionService.acknowledgedResult` 只读同一采购自动分析操作已经提交的 ACK。重新核对冻结正文、计划、明细顺序及每条引用，拒绝来源变化、越界引用、混用模型或损坏记录。外部调用保持 UNKNOWN，不重发、不重置预算，不接纳未提交的返回内容。预算与合同原有提取语义不变；超时清理的内容不恢复。
- 采购任务仍以案件版本与租约控制写入。后续分段返回异常时，保留独立核实的内容及已经完成的窗口，文档保留未完整完成状态，不把部分提取发布为全文完成。
- 公共人民币解析支持“人民币2180000元整”等带明确货币单位的阿拉伯金额，仍拒绝无单位的任意“整”后缀、超过分精度及夹带另一个金额的表达。预算、采购、合同共用解析器。
- 表格金额优先使用本页明确且唯一的货币表头，不受历史业绩、注册资本等其他页面的“万元”影响。金额与表头形成连续逐字引用；同页单位冲突、数字子串、金额用途不符仍不接受。报价不填充预算或中标金额，年度/分包/单价不混作整体金额。
- 长文上下文按业务主题优先选取具体付款比例、建设/交付期限等条款，目录与页码不消耗业务输入配额。引用仍保持原定位与逐字内容，不扩大历史业绩为当前事实。
- 语义结果增加问题依据分类：实际条款问题、材料范围、可选完善。缺少对照文件不列优先风险；已上传文件被误称未上传仍计为模型错误。确有原文要求的缺失附件、主观评分及限制条款保留。
- 页面增加常显的“材料要点”，按金额真实口径展示，带原文件名称、依据及复制。原有模块保留；没有依据的核对不堆砌提示。HTML 使用相同事实和可展示检查，不重新调用模型。
- 复核真实模型输出发现“系统checks”等内部术语。页面和 HTML 对“系统checks / Java checks”作有界的只读用词转换，称“系统核算结果”；不改写持久结果、文件名称或原文引用。模型提示同时要求使用业务用语。
- 历史结果不改写，不因读取旧结果补发模型。原失败案例的验收使用独立 QA 副本，不更新原案件及原提取台账。
