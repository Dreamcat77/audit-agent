# 采购材料业务语义优化

本轮维护当前采购批次自动审查入口。一批材料视为一个项目；项目识别不靠文件名相同，不要求用户先填写信息，也不引入提交审批流程。

## 处理顺序

1. 共用现有办公文档、PDF 和 OCR 读取链路。每份材料保留原文定位与文件哈希；分段提取有界输入，带入文件封面及章节背景，背景不能替代本段引用。
2. 模型先区分需求、资金、采购文件及澄清、供应商响应、评审成交的业务角色；采购人、代理机构、投标人分别保留。历史业绩、财务报表和人员履历不能成为当前项目的主体或金额。
3. 金额区分预算、最高限价、报价、中标、保证金，以及整体、年度、分包和单价口径。有来源的事实由模型提取，原文核验及金额计算仍由 Java BigDecimal 执行。缺信息不拼凑总价。
4. 跨材料核对项目和主体、采购范围与数量、金额关系及履约节点。名称差异和不同金额口径先交模型理解，不按字符串不同直接发布风险。
5. F10 招标文件合规性审查结合实际条款分析技术明确性、资格限制、评分依据、报价包含范围、付款验收与澄清。关键词只召回线索；最终问题需有语义解释和原文依据。供应商自主选择的品牌和自述所在地不能当作采购人排他要求。
6. 同一问题集中展示文件名称、实际约定、影响及修改建议。无风险依据不生成风险；尚未上传后续阶段材料不直接构成采购违规。未知或局部覆盖不得表示为全部合规。

## 实际修复

- “接受等效品牌产品”被旧品牌关键词直接生成为严重风险：规则候选现在只送模型复核，不作为最终风险同时发布。真实限制条件仍能由模型生成严重风险并沿用确认记录。
- 同一超预算报价被再次标记为成交价差异：金额核算单独展示，模型不重复发布；成交价比对必须有系统核算的同一供应商成交依据。真实成交价差异保留一次并使用具体标题。
- 按主题选择长正文中的技术、评分、付款、资格和澄清片段；历史业绩章节不挤占当前项目分析范围，未覆盖范围仍保留真实状态。
- 模型事实携带当前项目/参考材料及金额口径；表头万元单位、中文大写金额和自然语言预算保持可核验提取。
- 对“采购文件未提供评分细则”等内容缺失，不再误判为声称整份采购文件未上传而丢弃有效问题；报价单也进入需求范围核对。明确按整年一次性总价的成交金额，不因包含“一年”被误作年费。
- 整改建议必须消除原问题，不能把品牌限制改成品牌名单，也不能把地域资格或本地年限加分仅改成补交证明。
- 前端和 HTML 不展示待语义复核的规则候选；中文业务标题区分项目主体、预算适用范围和数量配置范围，保留原引用与历史结果。
