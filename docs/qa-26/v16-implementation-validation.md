## 本轮实现

- 预算：上传材料中的批复金额参与批次比较；补充超支、未批科目、漏报科目、用途差异和上传制度支持的审批环节/顺序检查。支持中文大写金额。风险及差异有来源材料，页面标红并支持差异清单导出。
- 预算审批记录：不再将“同意”当作审批环节，不把申报日期当成审批日期；关联同一份 Word 分散在不同段落中的项目名称、编号及审批记录。多个项目的歧义材料不拼接。
- 采购：主入口改为批次上传和自动结果，不要求用户填写项目、部门等业务字段；旧记录保留独立入口，结果页不放重复上传框。支持招标正文中的预算、报价比较、黑名单报警/站内通知、风险确认和完整 HTML 报告。
- 模型输出：个别条目格式错误不再清空其他有效条目；只保留通过结构与原文核对的内容，部分结果不会冒充全量完成。诊断日志保留字段位置、类型、数量，不记录材料或模型回答。
- 合同：自动分析成为默认入口，保留八大项及正式审核结果/确认；补充合同模板结构、份数、日期、附件、中文比例和实际违约金与上限比对。已提取项目名用于展示，缺少时生成名称，生成名不作为项目关联证据。
- 三模块复用统一材料解析边界及合同解析适配器。保留 Office 表格、原生 PDF/OCR、Word 内图片的处理能力；不把格式支持等同于任意材料必然完整识别。
- 前端保留 Chrome 109 字体与颜色兼容处理，增加可复用命令 `npm run build:customer`。

## 边界

- 拆分申报的 1 万/10 万是用户同意试运行的参考区间，正式审批门槛仍待甲方确认。
- 自动审批检查以用户上传的制度、审批记录为依据，不编造法规。用途措辞差异是核对线索，不直接认定错支。
- 黑名单当前复用系统已有有效数据库和报警事实；外部名单源及 OA 审批拦截不等于已经完成对接。
- 合同材料不足时八大项仍保留，有依据则展示内容，无依据则简短说明。正式建档仍不能伪造主体、金额或中标关系。
- 甲方原文件准确率、极端大扫描件完整性及 ARM64 现场运行仍需现场验证；本轮测试不保证任意文件全部正确。
- 本轮未制作甲方离线包，也未提交或推送 Git。
