# 测试计划

每例记录环境、源码指纹、输入批次、预期事实/风险、实际状态/结果、模型和DM8是否真实及证据定位。HTTP200只作传输证据。

1. P0：26版本/服务/配置只读核实，产物与配置备份及恢复核验；独立DM8、文件根、Redis namespace、认证和审计。
2. P1预算：Word/Excel/PDF/OCR，名称变化、金额大写、科目/金额缺失、多文件批复比对、超支/错支/漏项、三档累计边界、分页历史与刷新。
3. P2采购：既有12份完整项目一次上传，核对222600预算、212000中标、三家212000/216400/219800报价、9条物理明细；预审和F10真实上下文，风险/无风险反例；预算不冒充报价，计划不冒充已履约。
4. P3合同：正常采购/服务/租赁、字段缺失、金额/付款/中标/补充协议冲突、混合合同、附件失败、扫描与长表；上传零操作、报告、原文、刷新/重启及历史读取；正式合同原链路回归。
5. P4跨模块：共享解析/OCR/模型、权限、CAS幂等、迟到写入、UNKNOWN不盲重发、报告持久化；受控并发而非负载冲击。
6. 故障注入单列，不冒充实际模型成功。每个关键不变量有正向和对抗回归；技术异常与业务风险分开。
7. 全仓Java clean verify、前端测试/生产构建/Chrome109、Python全量；修复后重新实际部署/复测。
8. 通过后才执行补充交付：审查Git范围与密钥扫描、推送、安全最终部署核验、短名版本化ARM64离线包及最终包校验。
