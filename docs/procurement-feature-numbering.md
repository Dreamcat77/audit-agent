# 采购模块功能编号

## 规范编号

采购模块的对外展示与排期表统一使用以下编号：

| 排期编号 | 功能名称 | 代码内部历史标识 |
| --- | --- | --- |
| F03 | 供应商黑名单报警 | F03 |
| F06 | 三方询比价异常报警 | F06 |
| F10 | 招标文件合规性审查 | F07 |
| F11 | 围串标/拆分采购辅助识别 | F08 |

其中，`F10` 和 `F11` 是后续采购开发、需求沟通、前端展示、注释和业务文档必须使用的规范编号。

## 统一原因

招标文件合规审查和围串标能力在早期实现时分别使用了 `F07`、`F08` 的内部编号，与当前排期表中的 `F10`、`F11` 不一致。继续混用会造成需求、演示页面、验收项、测试证据和实现代码之间无法稳定追溯。

本约定以排期表作为业务侧唯一编号来源：面向用户和项目协作时使用 `F10`、`F11`；只有定位既有实现时才引用 `F07`、`F08` 历史标识，并应同时注明对应的规范编号。

## 改动策略

1. 优先统一前端展示、业务文档、需求说明和新增代码注释为 `F10`、`F11`。
2. 新增采购代码、测试名称和日志事件优先使用规范编号；如必须关联旧实现，在同一处写明历史编号。
3. 保持既有后端类名、接口路径、数据库表名、DM8 迁移脚本、规则编码和已持久化数据不变，避免破坏客户端兼容性、数据库升级顺序和历史数据查询。
4. 历史文档中属于其他业务模块的 `F07`、`F08` 不适用本约定，不能进行机械替换。

## 后续维护计划

1. 每次采购功能新增或修改时，检查用户可见文案、README、设计文档和测试说明是否使用规范编号。
2. 对仍使用旧编号的采购注释和文档逐步替换为规范编号；保留历史技术标识时补充映射说明。
3. 在接口、表名或类名发生破坏性升级前，单独评估版本化、数据迁移和客户端兼容方案；本约定本身不触发重命名。
4. 代码评审和验收以本文件及 `AGENTS.md` 的编号约定为准。
