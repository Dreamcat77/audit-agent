# 合同上传后自动分析：实现边界与维护说明

本说明对应当前工作树实现。阶段验收记录以 WORK_LOG.md 和 evidence 为准，代码存在不等于部署或真实环境验收通过。

## 独立案件

`ContractAnalysisCase` 是材料分析案件，不是正式 `Contract`、`ReviewSession` 或 `AuditTask`。通过既有 Project Intake 接收原件；Project 仅作为本次上传的既有文件容器，不伪造项目名称或合同编号。缺少合同金额、编号、正式合同 ID 不阻断独立条款分析。

前端开启 `VITE_CONTRACT_ANALYSIS_ENABLED`，后端开启 `AUDIT_CONTRACT_ANALYSIS_ENABLED` 后，新上传入口使用独立案件；原有正式审核记录入口保留。未启用开关时保持旧入口。开关必须在目标 schema 与回归验证通过后由部署配置显式启用。

## 处理链

上传操作先取得持久幂等接纳凭据，再使用原文件上传/分片上传能力保存原件。案件记录预期文件数，接收未完成时等待，不通过重复生成操作键制造另一案件。接收完成后封闭本批清单，后加文件不能污染原结果。

文件读取继续复用现有解析器、OCR Port、原件存储及不可变 `ProjectFileParseResult`。不新增全文副本。来源冻结文件 SHA、大小、parseResultId、parseVersion、canonicalText SHA；发布前再次核对。来源未知不等同于缺失。

后台先候选召回，再按文件或分段调用合同 AI，执行独立 F02 精确运算，最后对有明确关联的文件执行交叉核对。普通字段不足不阻断违约、验收、解除等独立条款。正常无风险合同也保留主要条款及已执行检查，不能把空 finding 当成空报告。

## 模型范围与结果校验

每片约 5,500 UTF-16 字符，重叠约 250 字符；分段边界保护代理对。每案最多 24 个模型单元，单文件最多 12 个基础分片，按文件广度分配。超过覆盖预算的部分明确披露，不宣称整份合同已审完。

模型单次默认预算150秒；Python容量1，Java独立Worker容量1。Java HTTP预算170秒，租约240秒，案件总时限30分钟。开始新模型调用前保留足够返回及落库时间。不得为了提高吞吐无限放大并发或盲目重试未知调用。

Python保持顶层协议、集合上限及每项结构校验。独立非法项不再抹除其他有效条款；拒绝计数传给Java，结果不标为完整。全项非法、未知顶层结构、越界集合仍拒绝。材料核实和可选建议按明确basis归入INFO类别；未知的实际风险代码不自动放行。

Java逐项将引用定位到本次提供范围的原文，允许空白差异但保存真实UTF-16原文偏移。数值必须出现在证据中。引用歧义、越界或字段角色不符时拒绝该项。原文定位成功仅证明来源，不能代替语义准确性验收。

风险与建议分开展示。当前未上传附件不能推断现实中附件不存在；局部分片不能推断整份合同没有某条款。明确付款安排冲突仍作为风险，不能用“建议”分类隐藏真正问题。

## 多文件

文件按各自角色与合同类型独立分析。跨文件配对要求明确的合同引用编号，或同项目编号下唯一合同；同批上传本身不足以证明关联。无法证明关联时保留独立事实，不混用主体和金额。

补充协议明确替换原条款时应说明新约定与适用条件，不将有效变更机械认成冲突。交叉模型仅获得选定证据，不能把该范围冒充完整全文。

F02 使用 `BigDecimal`、中文金额解析和公共精确运算核：金额大小写、物理明细乘法、可证明完整的明细合计、关联中标金额和供应商。必要操作数不足标记 `NOT_EVALUATED`。同名物理行不合并，局部表不冒充完整总价表。

## 持久性与恢复

DM8 `CONTRACT_ANALYSIS_CASE` 保存案件状态、租约、行版本和结果快照；原文仍在已有解析表。创建及每个检查点使用短独立事务并写长期业务操作审计；外部模型调用不持有数据库事务。

原子 CAS 同时校验案件身份、版本及租约。过期或被替换执行器不能发布结果。处理中进程中断后，已持久的RUNNING外部调用收为UNKNOWN，不以新名称自动重发。其他独立步骤可继续；总时限到达后必须形成终态。

终态分为 `COMPLETED`、`PARTIAL`、`DATA_INSUFFICIENT`、`FAILED`、`UNKNOWN`。存在可用事实、条款或检查时保留部分报告；全部不可读或必要服务全部不可用时如实说明。终态快照不可重写，GET与历史重开不创建模型任务。

权限按案件所有者隔离，并在后台重读有效账号角色。账号权限失效时停止自动执行，不冒充用户授权。自动决定不伪装人工确认，不放宽原正式合同晋升/审批的安全约束。

## 诊断及部署

现场技术诊断仅记录案件/请求ID、阶段、耗时、数量、限额、HTTP状态与安全原因码。不得导出正文、OCR内容、完整prompt、模型原始输出、凭据或业务数据库转储。测试环境授权的合成正文可用于独立Golden核对，不能因此开启现场正文日志。

部署必须先读取 DEPLOYMENT-MEMORY.md 和当前部署手册。独立案件DDL只增表和索引；实际目标schema与权限必须预检。代码回退不能撤销已执行DDL。禁止清库、刷库、跳过未知漂移或重放已执行SQL。

当前仍在合同隔离验收；三模块26阶段和最终GitHub/ARM64交付需依用户要求按后续顺序执行。具体通过/未通过项不得用本说明代替实际证据。
