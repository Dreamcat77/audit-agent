## 流程

启用独立功能开关后，用户选择一批文件，系统创建持久案件、接收原文件、后台解析/OCR、候选召回、合同语义提取、精确核算、关联材料比较并展示报告。用户无需填写编号、金额、甲乙方、材料角色或项目归属，也无需逐步启动审查。

新案件不是正式 Contract、ReviewSession 或 AuditTask。正式合同所需字段不足不会阻断独立条款审查；原正式审核入口及其权限/晋升条件保留，没有把系统自动决定冒充人工确认。

## 数据和结果边界

模型解释条款，Java使用BigDecimal核算金额。合同总价、预算、中标价及实际付款不混为同一金额角色；缺少操作数的规则为NOT_EVALUATED，不能显示通过。

原文引用必须在本次提供范围中唯一定位，并保存文件SHA、parseResultId/version、全文SHA和UTF-16偏移。非法项只影响该项及完整性，其他有效分析保留；全部无效时明确失败。来源真实存在不代表模型解释必然正确，真实样本另行审阅。

风险、上传范围外材料核实和可选建议分开。局部分片不能断言整份合同缺少条款。不同合同不因同批上传而强行合并；跨文件配对要求明确引用编号，或相同项目编号下唯一合同。明确变更旧条款不等同于冲突。

## 可靠性

短事务提交案件、检查点及长期业务审计；外部模型调用不占数据库事务。租约240秒，单次模型默认预算150秒，案件总期限30分钟，每案最多24个模型单元。Python及合同Worker采用受控并发。

接收未完成的操作保持原幂等身份，不把网络未知当失败重新建案。终态案件可历史重开，GET不触发模型。重启遗留的外部调用RUNNING收为UNKNOWN，不盲目重发；其他独立步骤和已验证结果保留。迟到执行器不能覆盖新版本。
