### 2026-10-16 只读 DM8 回归发现的 Worker 交接边界

启用既有只读调度回归后，正式 Mapper 的 SELECT-only CTE 能执行，但真实 Worker 在快步骤交接时出现 `RejectedExecutionException`，导致 BREACH 未在语义开始前完成。`Future.get()` 已返回不表示线程池工作线程已回到接纳位置；`cancel(true)` 已完成也不表示原计算退出。该缺陷与模型 LENGTH、历史 HTTP500、SQL 连接错误是独立问题。

只修现有 Worker 的本机内存接纳：单计算线程、容量为一的有界交接队列、非阻塞单扫描互斥，以及领取/恢复之前获得的每执行在途令牌。真实 Callable 退出和已取消任务退出分别用同一令牌 CAS 释放，旧任务的迟到 finally 不得清除新令牌。取消后仍执行的任务继续持有接纳权，本实例不得先领取另一条 DM8 任务再让其在本地等待；其他实例的既有租约/fencing 恢复不变。停止后不再领取，也不将迟到成功或异常发布成业务结果。未确认执行/持久化仍沿用原租约与 UNKNOWN 规则，不因线程池拒绝或停止而捏造 FAILED。

交接队列只覆盖已完成 Callable 到线程池再次接纳的短边界，不成为第二套业务任务队列，不增加并发、数据库结构、模型调用、Prompt 或预算。验证须含 afterExecute 屏障、取消但不退出、并发扫描、未开始即取消、关闭及旧令牌迟到反例，并重跑只读 DM8 调度回归。该回归使用真实 SQL 和 Worker、测试事务边界，不能表述为新的正式 ReviewRun/模型链路已经完成。

关闭门禁还覆盖真正开始 Callable 和进入 `markExternalRequested` 回调之前。已进入的短事务可以返回，已经出站的调用、忽略中断的内部计算或其已开始持久化不因 `close()` 自动消失；本类不引入跨外呼长锁，也不提供通用取消工作流。本机维护仍须证明所属 OS 进程退出和同库写者停止后才能备份，不能把调用 `close()` 直接当作完整停写证明。

### 2026-10-16 Review 定时入口与文件扫描的隔离
